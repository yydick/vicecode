# AOT 不兼容性报告（TypePHP）

> 本文档记录**核心源码**为配合 AOT（TypePHP）编译而必须遵守的约束，以及本仓库为满足它们
> 所做的**具体偏离**（改了什么、为什么不改变运行时行为）。
>
> ⚠️ **验证状态：全部条目均未用真实 TypePHP 工具链复核。**
> 本仓库**没有任何 AOT 构建设施**——没有构建脚本、`composer.json` 里没有相关依赖、CI 无相关步骤；
> 「产品版」是仓库之外的计划，不在本仓库的交付范围内。因此下面每条约束都只是**本仓库源码注释里
> 已经记下的结论**，本文档的职责是**把它们汇总到一处并标清出处**，而不是替编译器下断言。
> 真要把本文档当作编译前置条件使用之前，请先按文末清单逐条核对。

## 适用范围

- 只管**编入二进制的核心源码**（`src/` 等）。
- **插件不受本文档约束**：产品版不把插件编进二进制，插件由内嵌 Zend 运行时解释，
  插件文件写普通 PHP 即可（`src/Plugin/PluginInterface.php:13-16`）。

## 约束清单

编号是本文档自己的，供交叉引用。

### ① 全局声明要求

- **约束**：核心源码需满足 AOT 所要求的「全局声明」写法（符号在编译期可见）。
- **依据**：`src/Plugin/PluginInterface.php:15` 在列举「AOT 编码规范」时提到。
- **本仓库的遵守方式**：无已知偏离点。
- **验证状态**：**未验证**。本仓库没有需要这条约束的特殊写法，因而也没有可对照的偏离点；
  这条的具体语义（哪些声明形式不允许）**本仓库从未展开**，需要时另查工具链文档。

### ② `resource` 不能赋给 `array` 类型属性

- **约束**：AOT 的严格类型检查会**拒绝**把 `resource` 赋给声明为 `array` 的属性。
- **依据**：`src/Terminal/PtyProcess.php:23-27`。
- **偏离点**：`PtyProcess::$pipes` 声明为 `mixed`，并在属性上保留
  `@var array<int, resource>` 供静态分析与读者理解。
  - 起因：`proc_open()` 的 `$pipes` 是引用参数，回填进去的是 **stream resource**。
  - **标准 PHP 下 `array` 属性本来就接受 resource 元素**（`array` 不是泛型容器，不做元素类型检查），
    因此改成 `mixed` **不改变任何运行时行为**，纯粹为编译兼容。
  - 代价：类型信息从语言层降级到注释层，丢了静态检查——这是刻意的取舍。
- **验证状态**：**注释结论，未验证**。

### ③ 禁 `Closure::bind`

- **约束**：AOT 不支持 `Closure::bind`。
- **依据**：`src/Plugin/PluginLoader.php:11`、`src/App.php:288`。
- **偏离点**：**不使用 composer autoload 加载插件**——其实现依赖 `Closure::bind`；
  改为在核心代码里运行时 `require_once` 入口文件。
  - `src/App.php:288` 同步注明插件实例化路径刻意避开 `Closure::bind`。
  - 用户级配置里的插件也**不得**写进 `composer.json` 的 `autoload`
    （`docs/plugins.md` §6「加载机制与容错」）。
- **验证状态**：**注释结论，未验证**。

### ④ 文件级 `require` 受限

- **约束**：AOT 对**文件级**的 `require` 有限制；`require` 应发生在**方法体内**。
- **依据**：`src/Plugin/PluginLoader.php:11`、`:52`。
- **偏离点**：`PluginLoader::load()` 中的 `require_once $file` 位于**方法体内**（非文件级）。
  - 配套用 `class_exists($class, false)` 检查类是否已存在——第二个参数 `false`
    表示**不触发自动加载**（文件刚被 `require`，类应已存在）。
- **验证状态**：**注释结论，未验证**。
