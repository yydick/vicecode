# 开发里程碑（基于 PLAN.md 拆解）

> 本文件把 `PLAN.md` 的总目标拆成可交付、可验收的里程碑。每个里程碑内的需求按 **P0 / P1 / P2** 分级。
>
> **优先级定义**
> - **P0（必须通过）**：缺了里程碑就不成立，是核心功能，必须全部达标才能算该里程碑完成。
> - **P1（应当完成）**：重要功能，显著影响可用性；若跳过需有明确理由并记录。
> - **P2（锦上添花）**：增强项，时间允许再做，不阻塞里程碑。

**通用验证约定**
- 手动验证：在真实终端（≥80×24，建议 120×40）运行 `php bin/tui.php`，按描述操作观察。
- 纯逻辑单元验证：对 `Buffer` / `StreamParser` / `KeyParser` / `GitClient` 等无 I/O 依赖的纯函数写 PHPUnit 用例。
- 协程验证：用 `Swoole\Coroutine\run()` 包裹，断言非阻塞（运行不卡死主线程）。
- 干净退出：每次手动验证结束用 `Ctrl+C` / `ESC` 退出，确认终端恢复正常（无乱码、无残留 raw mode）。

## M0 — 集成骨架（Swoole 驱动 php-tui）

目标：验证最大不确定性（Swoole 事件循环 ↔ php-tui 渲染/输入）跑得通，画出静态 VSCode 分屏，键鼠能切换焦点。

### R1 项目脚手架  [P0]
- **需求描述**：Composer 初始化，PSR-4 自动加载，建立 `bin/tui.php` 入口与 `src/` 目录骨架（Core / Panels / Editor / AI / Git / Terminal）。安装 `php-tui/php-tui` 与 `php-tui/term`。
- **达标项**：`composer install` 成功；`php bin/tui.php` 可启动；目录结构与 PLAN 七一致。
- **验证方式**：执行 `composer validate`（无错误）；`php bin/tui.php` 能进入后续定义的界面（不报类找不到）；`composer dump-autoload` 后无缺失。

### R2 协程主循环与终端生命周期  [P0]
- **需求描述**：`Swoole\Coroutine\run()` 内初始化 php-tui `Terminal`，进入 alternate screen + raw mode，启用鼠标捕获；用 `Swoole\Timer` 定时 `draw`；协程 `fread` 读 STDIN。退出时 `defer` 恢复终端。
- **达标项**：程序启动即全屏；`Ctrl+C`/`ESC`/异常退出都能干净恢复终端（无乱码、光标可见、回显恢复）；渲染循环持续运行。
- **验证方式**：手动启动→`Ctrl+C` 退出，检查终端正常；故意抛异常退出，确认仍恢复；用 `strace`/日志确认 draw 由 Timer 驱动（非忙等）。

### R3 静态 VSCode 布局  [P0]
- **需求描述**：用 php-tui `Layout` 嵌套画出：左 Sidebar、中上 Editor、中下 Terminal、右上 AI 交互流、右下 AI 输入框、底部 StatusBar；各面板渲染边框与标题占位。
- **达标项**：启动即见六区静态分屏，比例符合 PLAN 三（Sidebar≈30 列、AI≈45 列、右段上≥60%/下≈3 行、StatusBar 1 行）；无布局报错、无重叠。
- **验证方式**：手动目测；调整终端尺寸后（MIN/MAX）检查布局自适应不崩；截图比对（或录制 asciinema）确认结构。

### R4 键鼠输入接入与焦点切换  [P0]
- **需求描述**：实现「键鼠统一」输入解析（方向键/功能键/字母 + SGR 鼠标转义）；键盘 `Tab`/方向键切换焦点；鼠标单击面板切焦点、单击 Sidebar 标签切 Expl/Git/Search；命中测试依赖 `AppState` 中保存的面板布局矩形。
- **达标项**：键盘与鼠标都能改变当前焦点面板并高亮；点击 Sidebar 标签能切换三个子标签；鼠标坐标正确命中对应面板。
- **验证方式**：键盘 `Tab` 循环焦点，观察高亮跟随；鼠标点不同面板，焦点随之切换；点 Sidebar 三个标签分别切换；误点（坐姿外区域）不崩溃。

### R5 窗口 resize 处理  [P1]
- **需求描述**：监听 `SIGWINCH`，终端尺寸变化时重算布局并立即重绘。
- **达标项**：拖动终端窗口改变大小后，分屏比例重新计算、无错位。
- **验证方式**：运行中日间缩放终端，观察布局实时正确；极端小尺寸（如 40×10）下不崩溃、面板可最小化或提示。

### R6 启动调试 overlay（F12）  [P2]
- **需求描述**：按 `F12` 显示调试层：当前 fps、最近事件类型、各协程数。
- **达标项**：`F12` 可开关调试层，信息实时更新。
- **验证方式**：开启后做几次操作，确认事件类型/帧率显示正确，关闭后界面恢复。

**M0 出口标准**：R1–R4 全达标，R5 至少基本可用，程序可稳定进入/退出，`php bin/tui.php` 显示静态分屏且键鼠能切焦点。

## M1 — 资源管理器 + 编辑器（查看 + 基础编辑）

目标：能浏览项目文件树、打开文件、查看（行号/高亮）、做最基础编辑与保存。

### R1 资源管理器目录树  [P0]
- **需求描述**：协程 `scandir` 递归构建目录树（懒展开：展开节点时才读子目录）；支持折叠/展开、上下移动选中、高亮。
- **达标项**：启动后 Sidebar 默认显示 Explorer 树；方向键移动、`Enter` 展开/折叠目录；打开大目录不阻塞界面（协程非阻塞）。
- **验证方式**：进入含上千文件的目录，操作流畅无卡顿（协程不阻塞渲染）；单元测 `scandir` 协程返回结构正确。

### R2 打开文件载入 Buffer  [P0]
- **需求描述**：选中文件 `Enter` 用协程读文件内容写入 `Editor\Buffer`（行数组），编辑器面板渲染内容 + 行号。
- **达标项**：打开文本文件后编辑器显示内容带行号；二进制/超大文件有保护（超阈值提示或不载入）。
- **验证方式**：打开一个中等 PHP 文件，确认内容/行号正确；打开 50MB 文件确认不卡死、有提示。

### R3 编辑器滚动与光标移动  [P0]
- **需求描述**：方向键、`PageUp/PageDown`、`Home/End` 移动光标与视口滚动；内容超出可视区可滚动。
- **达标项**：长文件可正常上下/翻页浏览，光标位置正确，视口边界处理正确。
- **验证方式**：打开长文件，逐项操作确认滚动与光标一致；边界（首行/末行）不越界。

### R4 基础编辑与保存  [P0]
- **需求描述**：`Buffer` 支持插入字符、退格、回车换行、删除；`Ctrl+S` 用协程写回文件；标题显示未保存标记 `*`。
- **达标项**：能输入/删除文字，保存后文件落盘、标记清除；保存失败有提示。
- **验证方式**：编辑后 `Ctrl+S`，`cat` 文件确认改动写入；只读文件保存时报错提示而非崩溃。

### R5 语法高亮  [P1]
- **需求描述**：引入 `scrivo/highlight.php`（或自写轻量 tokenizer），按文件扩展名着色；高亮在 Buffer 渲染时应用。
- **达标项**：PHP/JSON/Markdown 等常见文件有基本着色，且不影响滚动性能。
- **验证方式**：打开 PHP 文件确认关键字/字符串/注释着色；着色开启/关闭下滚动帧率无明显下降。

### R6 编辑器鼠标交互  [P1]
- **需求描述**：滚轮滚动编辑器内容；点击行定位光标/视口。
- **达标项**：滚轮可滚动长文件；点击位置映射正确行。
- **验证方式**：滚轮滚动确认内容跟随；点击不同行光标/视口匹配。

### R7 多 Buffer / 多标签页  [P2]
- **需求描述**：同时打开多个文件，Sidebar 或编辑器顶部显示已开标签，可切换。
- **达标项**：可开多个文件并切换，未保存状态各自保留。
- **验证方式**：开 3 个文件切换，确认内容与未保存标记独立。

### R8 未保存标记与确认  [P2]
- **需求描述**：退出/切换有未保存文件时提示确认。
- **达标项**：有未保存改动退出时弹确认。
- **验证方式**：编辑未保存退出，确认有提示且可选择取消。

**M1 出口标准**：R1–R4 全达标，能浏览文件并做基础编辑保存。**注：M1 的 P1/P2（R5/R7/R8）仍在此里程碑收尾，未完工前不标记 M1 完成。**

✅ **M1 已完成（2026-08-28）**：R1–R8 全实现，`tests/m1_smoke.php` 全 PASS，`tests/pty_run.php`/`tests/pty_drive.php` 真实 pty 验收 exit=0。R6 编辑器鼠标交互也已实现并通过测试。

> **补（2026-08-29）：侧栏鼠标交互对齐 VSCode 习惯**。用户反馈「双击目录没反应」——
> 原实现里点目录只 `selectedPath` 选中，展开/折叠只能按 `Enter`，与 VSCode「双击目录=展开/折叠」不符。
> 现约定：**单击文件=打开进编辑器**（用户认可，不改）；**单击目录=只选中、不展开**（避免误触折叠）；
> **双击目录=展开/折叠**。终端没有双击事件，由 `App::consumeTreeDoubleClick()` 按
> 「同一条目 + 同一屏幕行 + 400ms 内」合成（判定成立即清空记录，防三击连 toggle 抵消）。
> 测试：`tests/m1_smoke.php` 第 9 节、`tests/pty_mouse.php`（真实 pty 双击目录）。
>
> **补 2（2026-08-29）：单击行首三角（▶/▼）也能展开/折叠**（VSCode 支持，之前列为待定）。
> 命中列由渲染布局推出：**边框 | marker「» 」2 列 | 缩进 2\*depth 列 | 三角 1 列 + 其后空格 1 列 | 名称**，
> 即三角在 `sidebar.x + 3 + 2*depth`（实测 120x40 下 depth=0 的三角在 x=3，行样式 `│» ▶ .docs/`）。
> 命中区取「三角 + 其后空格」共 2 列——只判三角那 1 列太窄、很难点中。
> 见 `App::hitTreeArrow()`。点三角时清空双击记时，避免与后续点击误合成双击。
>
> 现在的鼠标约定（与 VSCode 一致）：
> - 单击文件 → 打开进编辑器
> - 单击目录名 → 只选中，不展开/折叠（避免误触）
> - **单击行首三角 → 展开/折叠**
> - **双击目录 → 展开/折叠**

## M1.5 — 底层切到 Swoole（M1 与 M2 之间的插入任务）

目标：把应用运行时/事件循环底层从「纯 php-tui/term 阻塞读」换成 **Swoole 协程**，同时保留 php-tui 负责渲染、保留 php-tui/term 负责 Terminal I/O，以避开 M0 踩过的坑（`Swoole\Event::add(STDIN)` 在真实 pty 不触发读键）。

### 背景与约束
- M0 曾因 Swoole 直接驱动终端读键失败而回退到 php-tui/term 的 `BlockingTtyEventProvider`（`stream_select` 阻塞等键）。详见 `project_php_tui_facts.md`。
- 本任务**不是**让 Swoole 再接管终端读键，而是把它作为**协程运行时/事件循环底座**：用 `Swoole\Coroutine\run()` 启动，STDIN 用 **`Swoole\Coroutine::waitEvent(STDIN, SWOOLE_EVENT_READ)` + 非阻塞 `fread`** 协程读（注意：`Swoole\Coroutine\System::fread` 在 6.0 已移除，不能再用；`SWOOLE_HOOK_STDIO` 对真实 TTY 的 `fread` 也不会协程化、会阻塞调度器），`draw` 由主循环「有事件才重绘」驱动，用协程跑 M2 命令与 M5 LLM SSE。
- **最终落地方案**（见 `docs/swoole_study.md`）：读键协程 `while (!$app->quit) { waitEvent(STDIN,READ,1.0); 可读则 fread; EventParser 解析后 push Channel }`；主循环 `while (!$app->quit) { $ev=$ch->pop(0.05); 超时则 isEmpty 查后台重绘信号再 continue; 否则 handle+draw }`；`Coroutine\defer` 还原终端；默认 `SWOOLE_HOOK_ALL & ~SWOOLE_HOOK_STDIO`。

### R1 协程运行时底座  [P0]  ✅ 已达标
- **需求**：`bin/tui.php` 改为在 `Swoole\Coroutine\run()` 内启动；STDIN 用协程读（不阻塞渲染/其他协程）；`draw` 由事件驱动。
- **达标**：真实 pty 下键鼠输入正常、画面随帧刷新、退出时终端干净还原（无花屏、回显恢复）。
- **验证**：`tests/pty_run.php` + `tests/pty_drive.php` 真实 pty 干净退出（exit=0）；`tests/m1_smoke.php` headless 仍 PASS。

### R2 终端生命周期接入 Swoole  [P0]  ✅ 已达标
- **需求**：alternate screen / raw mode / mouse capture / 还原，由 Swoole 协程上下文下的 php-tui/term 完成。
- **达标**：与 M0 同等干净退出；与 R1 协程读共存（真实 pty 验证通过）。

### R3 协程能力预留（为 M2/M5）  [P1]  ✅ 已打通最小通道
- **需求**：暴露「起一个协程跑耗时 I/O 并把结果回写 App 状态」的最小通道。
- **达标**：`TUI_DEMO=1` 后台协程 `sleep` 后写 `$app->message` 并 push `$redraw` 信号、主循环非阻塞消费并重绘，不阻塞渲染；`tests/coroutine_channel_test.php` headless PASS；`tests/pty_demo.php` 真实 pty 干净退出（exit=0）。

**M1.5 出口标准**：R1–R3 全达标（真实 pty 验证），R3 至少打通最小通道。Terminal I/O 仍由 php-tui/term 负责，Swoole 只做协程底座。

> 状态：**完成（2026-08-28）**。真实 pty 双工具 `pty_run`/`pty_drive` 均 exit=0；headless `m1_smoke`、`coroutine_channel_test` 均 PASS。踩坑记录见 `docs/swoole_study.md`（SWOOLE_HOOK_STDIO 对 TTY 不协程化、Channel::pop(0) 永久阻塞、`Coroutine\run` 需所有子协程退出才返回）。

## M2 — 终端命令运行器

目标：中下终端面板可接受命令、协程执行、流式显示输出与历史。

### R1 命令输入行  [P0]
- **需求描述**：终端面板聚焦时可输入命令（独立输入缓冲区），支持光标移动、退格、回车提交。
- **达标项**：聚焦终端后可正常输入命令并提交；输入不与全局快捷键冲突。
- **验证方式**：聚焦终端输入 `ls -la` 回车，进入执行流程；输入中方向键控制光标。

### R2 协程执行命令  [P0]
- **需求描述**：用 `Swoole\Process` 或 `Co::exec` 异步执行命令，分离 stdout/stderr。
- **达标项**：命令在协程中执行，不阻塞渲染线程；能拿到退出码与两段输出。
- **验证方式**：运行 `sleep 2 && echo hi`，界面在等待期间仍可响应其他操作（如切面板）；确认 stdout/stderr 分流。

### R3 输出流式渲染  [P0]
- **需求描述**：命令输出逐块写入终端输出 buffer 并随帧刷新（流式打字感）。
- **达标项**：长输出（如 `cat` 大文件）逐步显示而非卡住后一次性出现；超长输出可滚动。
- **验证方式**：运行 `seq 1 1000`，观察输出随执行逐步出现；滚动查看历史。

### R4 命令历史  [P0]
- **需求描述**：`↑/↓` 在历史命令间切换；历史持久化于会话内。
- **达标项**：提交过的命令可用 `↑/↓` 召回。
- **验证方式**：执行若干命令后 `↑` 召回并回车重跑。

### R5 退出码与错误着色  [P1]
- **需求描述**：非零退出码在输出末提示；stderr 用不同颜色。
- **达标项**：失败命令显示退出码；stderr 可见区分。
- **验证方式**：运行 `false` 或 `ls /noexist`，确认退出码/stderr 着色。

### R6 终端面板滚轮滚动  [P1]
- **需求描述**：滚轮在终端输出区滚动回看。
- **达标项**：滚轮可滚动输出历史。
- **验证方式**：产生多屏输出后滚轮回看。

### R7 可中断执行  [P2]
- **需求描述**：运行中 `Ctrl+C` 杀掉当前子进程。
- **达标项**：`Ctrl+C` 能终止正在跑的命令。
- **验证方式**：运行 `sleep 100`，`Ctrl+C` 终止并提示。

**M2 出口标准**：R1–R4 全达标，能输入命令、协程执行、流式看输出、用历史。

## 已知问题

### ✅ 已修复（2026-08-28）：`tests/m1_edge.php` 光标反显列精度

- **现象**：断言光标在 `(34,1)`，实际 `(33,1)`。
- **根因**：`PhpTui\Tui\Style\Style::addModifier()` 是**原地修改并返回 `$this`**（`vendor/php-tui/php-tui/src/Style/Style.php:88`）。
  而 `App::editorContent()` 对整行只构造一个 `Style::default()` 实例，`clipLineSpans()` 展开成字素后
  所有字素**共享该实例** → 给光标字素加 `REVERSED` 时整行都被反显 → 扫描找到的第一个反显格是行首而非光标。
- **影响**：编辑器光标视觉上是「整行反显」而不是单个字符反显。
- **修复**：`clipLineSpans()` 里反显前先克隆 —— `(clone $st)->addModifier(Modifier::REVERSED)`。
  已排查其余 `addModifier` 调用点（含 `Highlighter::styleFor`），均为新建实例，不受影响。
- **验证**：`m1_edge` 全 PASS（光标落在 `(34,1)`）；修复后首行只有光标所在格反显（修复前整行 3 格）。
- **教训**：php-tui 0.2.1 的 `Style` 是**可变对象**（`fg()`/`bg()`/`addModifier()` 都原地改并返回 `$this`）。
  任何「共享 Style 实例 + 局部改样式」的地方都要先 `clone`，否则会污染所有持有同实例的字素/行。

### ✅ 已修复（2026-08-29）：编辑器输入串出现在两处（第 34 行行首 + 第 16 行）——「幽灵行」

- **现象**：打开文件后，把光标移到第 34 行行首输入字符串，第 16 行同步出现本不属于它的内容。
- **数据层一直是对的**：直接设 `cursorRow=33` 逐字符插入 `ZZZ`，只有 `lines[33]` 被改，渲染文本里 `ZZZ` 只出现 1 次。
- **真凶：行溢出触发 php-tui 折行**（三个因素叠加，缺一不可）：
  1. **`Highlighter::parseHtml` 的 `strncmp` 缺偏移参数**（`src/Editor/Highlighter.php`）。
     `strncmp($html, '<span class="hljs-', 18)` 比的永远是**字符串开头**而非位置 `$i`，
     导致除首个标签外所有 hljs span 标签都被当纯文本吞进 buf。
     实测 `plan/MILESTONES.md`：高亮行数 331（实际 494）、216 处无效 UTF-8、
     编辑区直接渲染出 `<?phpeyword">declare class="hljs-numbe` 这样的标签碎片。
     修法：`substr($html, $i, 18) === '<span class="hljs-'`。
  2. **`App::cpWidth` 自维护 Unicode 宽度区间表，与 php-tui 不同源**。
     php-tui 用 `mb_strwidth()` 累加行宽（`StyledGrapheme::symbolWidth()`）；我们的表漏了
     韩文音节 `U+AC00–D7A3`（我们算 1、`mb_strwidth` 算 2）等。修法：删表，直接用 `mb_strwidth()`。
  3. **`App::clipLineSpans` 裁剪只比字素起始列**（`$w < $scrollLeft + $textW`）。
     宽字符占 2 列，在边界处会溢出 1 列。实测第 6 行被裁到 40 列而 `textW` 只有 39，
     行总宽 44 > 面板内宽 43。
- **触发链**：行宽超出 1 列 → `ParagraphWidget`（默认 `Wrap::None` → `LineTruncator`）**不截断而是折行**
  （`LineTruncator::nextLine()` 在超宽时 `yield` 当前累积行后再 `yield` 剩余部分）→
  该行占 2 个屏幕行 → **后续所有行整体下移、行号栏被挤掉**。
  折行会逐行累积，越往错位越严重，所以第 16 行会显示第 34 行附近的内容碎片。
- **修法**：裁剪改用「起始列 + 自身宽度 <= 右边界」；列宽计算与 php-tui 同源（`mb_strwidth`）。
- **验证**：`tests/editor_render_check.php`（高亮行数守恒 + 屏幕行号严格连续 + 屏幕文本等于文件内容，
  覆盖 120x40 / 100x30 / 80x24 三种视口）、`tests/diff_invariant2.php`（忠实终端模型的差分不变量）。
  两个测试都做过「回退修复即 FAIL」的反向验证：
  - 回退第 3 项 → 报 `屏幕第 16 行行号='要' 应为=16`（正是用户报的第 16 行）；
  - 回退第 1 项 → 报 `屏幕='<?phpeyword">declare class="hljs-numbe'`。
- **排除掉的错误方向（别再走一遍）**：
  - **不是差分渲染残留**。用 `DummyBackend` 复现出一堆「残留」，但它逐格写入、**不模拟宽字符覆盖右邻格**，
    是模型缺陷造成的假阳性。换成忠实模拟宽字符覆盖的 backend 后，差分是全绿的——
    `Display\Buffer::diff()` 跳过宽字符占位格在真实终端上是**正确**的。
  - 也**不是**竖向滚动后 `scrollTop` 与光标状态不一致（数据层早已验证正确）。
- **教训**：
  - 复现工具自身的保真度要先验证，否则会拿着工具缺陷当 bug 查。
  - 编辑器这类要求行严格对齐的场景，必须保证每行总宽 ≤ 面板内宽，且列宽算法与渲染库同源。
  - **折行发生在 `ParagraphRenderer` 写 buffer 阶段，与 backend 无关**，故这类验证不必依赖 pty。

## 验收与流转建议

1. **逐里程碑交付**：每完成一个里程碑，先让 R1–R4（P0）全部达标，再做 P1/P2；P0 未达标不进入下一里程碑。
2. **持续集成**：纯逻辑模块（Buffer / StreamParser / KeyParser / GitClient 解析）配 PHPUnit，随 M1–M5 逐步补齐用例。
3. **演示记录**：每个里程碑结束录一段 asciinema 或截图，作为「验证方式」的实物证据，便于评审。
4. **M0 是硬门槛**：Swoole↔php-tui 集成若卡住，后续里程碑无从谈起，优先投入验证。
